## 1. 一句话定义与产品定位

**上下文管理器**负责把 AI 推理所需的业务消息组装后发给 Hermes。

它挂在 ProjectLens 会话层（租户 + 群 + 人 + 项目），不改 Hermes 核心，也不用 Hermes `/branch` 直接管飞书群聊。Hermes 单轮工具循环内的落盘与压缩继续用；本方案只管**跨轮会话**的组装、预览、分叉与轨迹落盘。

```text
飞书群 @ 机器人
  -> 上下文管理器弹出预览 / 选择界面
  -> 用户确认待发集合（默认或自定义）
  -> 按时间排序组装业务消息
  -> 发给 Hermes
  -> 整次 GenAI trace 落盘为 json（取代原 AgentRun 表体）
```

## 2. 要解决的问题

| 问题 | 说明 |
| --- | --- |
| 默认上下文不可控 | 自动带最近轮次/摘要时，旧讨论、过期结论会污染本次回答 |
| 群内讨论难复用 | 两次 `@` 之间的群聊讨论若不引用，用户只能重新总结一遍 |
| 同上下文多角度 | 方案 A/B、历史决策对比需要分线，而不是在同一会话里互相覆盖 |
| 发送前不可见 | 用户不知道本次模型实际会看到哪些条目 |
| 轨迹难沉淀 | 仅有审计编号无法支撑后续 agent 从完整过程提炼 skill |

## 3. 本期范围与非目标

### 3.1 本期范围

- 仅飞书群聊 `@` 机器人路径。
- 四个能力：滑动窗口与自定义引用、分支（fork）、飞书预览、GenAI trace 落盘。
- 群聊发言不落本地全文库，按需调飞书「获取会话历史消息」。
- 预览即实发（硬承诺）；不做「完整性警告」。
- **不要求**旧方案的「ContextSnapshot + 同一 renderer」架构；要求「卡片待发集合与顺序 = 实发集合与顺序」。

### 3.2 明确非目标

1. 取消勾选不删除飞书聊天、不回滚 Git/文件/数据库、不撤销已审批项目记忆。
2. 不全量监听并落库全部群聊消息。
3. 本期不做 trace 脱敏策略（另开代办）；不做 skill 自动沉淀（只存轨迹供以后用）。
4. 本期不把项目记忆、Evidence 做成上下文卡片上的第三类勾选项（对齐初步方案；它们仍按现有审批 / 工具路径工作）。
5. 不做「缺背景完整性警告仍可发送」的提示流。
6. 不开放 Apply、PR、deploy、rollback 等写操作。

### 5.1 基础上下文管理（滑动窗口）+ 自定义引用

#### 目的

在「够用的默认上下文」之上，让用户剔除噪声、点名补上群内讨论或旧对话，避免重复口述，也避免过期讨论污染回答。

#### 使用场景

1. 两次 AI 对话之间，群里已经讨论过一轮；新一次 `@` 时直接引用那段讨论，补全问题上下文。  
2. 讨论里已经写清疑问，用户不想再总结一遍，勾选相关消息后直接让模型识别意图。  
3. 跨午夜仍希望连续讨论时，默认池不因「换日」自动丢掉昨天条目；需要收窄时再用日期窗。

#### 行为约定

**默认窗口与压缩（对齐初步方案）：**

| 规则 | 口径 |
| --- | --- |
| 最近轮次上限 | 8 条用户提问原文（实现时从源码默认 6 改为 8） |
| 压缩触发 | 对话轮数超过 8（不含第 8 轮），即写入第 9 轮及之后触发 |
| 压缩范围 | 每次处理当前池中最旧的第 1～4 轮（含第 1 轮），移出原文池并进摘要（压旧留新） |
| 每轮摘要 | 用户原始问题 + 回答总结 + 证据唯一标识；「回答总结 + 证据标识」合计约 300 token；**用户原问题不计这 300** |
| 默认剔除非今日 | **不做**。默认沿用「摘要 + 近几轮」整池，避免跨午夜相关讨论断上下文 |
| 日期窗 | 可选粗筛；用户主动设置后才按窗过滤；窗外不删库 |

**可引用 / 可勾选对象（卡片侧）：**

- 会话侧历史对话（最近轮次、压缩前写下的引用条目、可检索的历史对话记录）
- 群聊消息（含未 `@` 机器人的发言；按需飞书接口拉取）

**不作为卡片勾选项（对齐初步方案）：** 项目记忆、Evidence。取消勾选只影响本次发给 Hermes 的内容。

**粗筛与细选：**

1. 粗筛：会话级日期窗（日期卡片写入；随分支走；未开窗则默认整池）。  
2. 细选：写入本会话引用清单；引用/转发群消息也算细选。  
3. 待发条目必须带时间字段；组装时按时间升序；缺时间不得进入待发集合。  
4. 引用清单默认只把「编号 + 短标题 + 时间」放进上下文；正文不默认塞入。每条须持久化取回键，并提供工具让模型按需取正文（见初步方案 §5.1）。

#### 验收（可测）

1. 最近轮次上限为 8；超过 8 轮触发压缩，且只压缩最旧的第 1～4 轮。  
2. 未开日期窗时，池内跨日的最近轮次与摘要仍进入默认待发集合（不做剔除非今日）。  
3. 细选一条会话历史或一条群聊消息后，该项出现在预览且实发包含该项元数据；模型可用工具按引用编号取回正文。  
4. 取消勾选某条后，实发不再包含该条；飞书原消息与项目记忆未被删除。  
5. 群聊历史不落本地全文；细选依赖飞书历史接口（权限不足时会话侧仍可用，群聊来源明确不可用）。

#### 冒烟

- `@` 机器人 → 看到默认「摘要 + 近几轮」整池 → 「直接回答」能跑通一轮 Hermes。  
- 「编辑上下文」勾选一条群消息 → 预览出现 → 发送后模型侧能看到该引用短标题；需要时可工具取回正文。

### 5.2 分支模式（fork）

#### 目的

让同一分叉点之前的上下文保持一致，之后按不同角度各自演进，互不覆盖——对齐 Hermes `/branch`：原线停住，只在新线继续。

#### 使用场景

1. 方案 A / 方案 B 对比：从同一讨论点分出两条线分别推演。  
2. 历史决策 A / B 对比：在同一批已引用材料上，分别按不同决策假设继续提问。

#### 行为约定

1. 卡片提供 **「新建分支」** 按钮：从当前线复制出新会话。  
2. **复制内容**：默认上下文（会话摘要 + 近几轮）、**日期窗**、**引用清单**（及当前细选/待发相关状态）。分叉时不调用模型重写历史。  
3. 新会话记录父会话编号与分支名；原会话停在分叉点，不再被后续提问改写。  
4. 卡片可 **切换已有分支**；发送时只在当前选中的线继续写入与组装。  
5. 同一群绑定同一时刻只有一条进行中的分支。  
6. **持久化与映射（防重启丢失）**：分支树、`parent_session_id`、分支名、停线状态、绑定键 → `active_session_id`、同绑定下兄弟分支索引，以及每条线上的摘要/近几轮/引用清单/日期窗/待发相关状态，均写入与 `ConversationSession` 同一持久化后端（默认 SQLite）。禁止只存在进程内存；新建/切换/停线须立刻落盘。

#### 验收（可测）

1. 新建分支后，新线含复制后的摘要、近几轮、日期窗、引用清单；原线不再接收后续提问写入。  
2. 切换到分支 B 后提问，只写入 B；切回 A 后提问只写入 A。  
3. 分叉点之前两边一致；分叉后各自追加互不影响。  
4. 未选中的分支不会因另线提问被改写。  
5. 新建分支 B 后重启服务，卡片仍能列出 A/B，切到 B 提问只写入 B。

#### 冒烟

- 在线 A `@` → 新建分支 B → 在 B 提问成功 → 切回 A 提问成功，且两边最近轮次不串写。  
- 新建 B 后重启 → 仍可切换到 B 并继续提问。

### 5.3 飞书端上下文预览

#### 目的

让用户在发送前直观看到「本次会引用哪些信息」，并保证所见即所发，消除「模型偷偷多看了什么」的不确定。

#### 使用场景

1. 每次 `@` 机器人提问前，确认默认是否合适，再决定直接发或改引用。  
2. 编辑后需要立刻看到 token 预算与待发列表，避免超预算或漏引关键讨论。

#### 行为约定

**何时弹出：** 每次 `@` 机器人都弹出预览与选择界面（群聊提问均需 `@`，故每次提问都经过该步）。

**卡片必须包含：**

1. **Token 预算**（估算本次待发占用）。  
2. **已按时间排序的待发列表**（默认项与细选项同一张卡；默认项标「默认」，细选项标「引用」）。  
3. **三个入口**（防止后续开发偏离）：

| 入口 | 含义（必须按此实现） |
| --- | --- |
| **直接回答** | 使用上下文管理器选择的默认内容：会话摘要 + 近几轮消息（未开日期窗则整池带入；有日期窗再按窗过滤），按时间排序后直接发给 Hermes，不要求用户逐条确认 |
| **编辑上下文** | 用户自定义：可引用历史对话、群聊消息，或取消勾选默认已选中的消息；变更后刷新预览 |
| **选择更多历史** | 先按时间（日期窗）粗筛，再逐条细选要引用的消息；写入引用清单并刷新预览 |

**预览即实发（硬承诺）：**

1. 预览卡片上的待发集合 = 实发给 Hermes 的集合。  
2. 发送时**不得**再追加预览上未展示的最近轮次或其它条目。  
3. 从预览去掉的条目，本次不得发送。  
4. 本期不做不可变 ContextSnapshot 产品形态；若将来升级，另开规格。

#### 验收（可测）

1. 每次 `@` 均出现含 token 预算与三入口的卡片。  
2. 「直接回答」实发内容与预览默认列表一致（条目与顺序）。  
3. 「编辑」取消一条后，实发不含该条；「编辑」新增一条后，实发含该条。  
4. 「选择更多历史」经日期粗筛后细选，选中项进入预览与实发。  
5. 服务端组装只消费预览待发集合，集成测试可断言无额外注入。

#### 冒烟

- `@` → 预览出现 → 直接回答通一轮。  
- `@` → 编辑去掉一条默认 → 预览更新 → 发送后日志/trace 中 messages 不含该条。

### 5.4 GenAI Trace 落盘（供后续 skill 沉淀）

#### 目的

把每一次指令周期的完整过程留下来，供后续另一个 agent 在沙箱里提炼、试跑并沉淀 skill；避免只有编号、无法还原「当时怎么跑的」。

#### 使用场景

1. 后续 agent 读取 `data/` 下 json，提炼候选 skill → 沙箱执行确认能跑通 → 入库；跑不通则标记失败。  
2. 按项目找回某次完整问答与工具链，做复盘或回归对照。

#### Trace 定义（OpenTelemetry GenAI）

从用户发出这条指令，到 AI 完成本次指令并给出回复，中间产生的**全部 messages 与相关状态**算一次 trace。不是只记一个编号，而是整份落盘。

#### 落盘约定

| 项 | 口径 |
| --- | --- |
| 内容 | 用户指令原文；实际发给模型的 messages（含预览上下文与系统侧说明）；AI 中间与最终回复；tool result 正文（含失败）；工具列表；运行时状态；trace 起止与各条时间戳 |
| 路径 | 文件在仓库 `data/` 下（如 `data/traces/...`）；**json 文件本身取代现有 AgentRun 表体** |
| 索引 | SQLite 存轻量索引：至少含文件路径、tenant/project、时间、trace 标识，便于按项目找回 |
| 保留 | 默认 30 天（到期清理策略实现时一并做） |
| 脱敏 | **本期不做**；策略另开代办 |
| Skill | 本期只存轨迹；不自动写 skill 库 |

每条信息必须有时间戳；读回时按时间戳排序还原。缺时间戳不得写入轨迹文件。

#### 验收（可测）

1. 一次 `@` 完整跑通后，`data/` 下出现对应 json，且含用户消息、实发 messages、最终回复、至少一次 tool result（若有工具调用）。  
2. SQLite 索引可按 `project_id` 查到该文件路径。  
3. json 内条目均有时间戳；缺时间戳的写入被拒绝或测试覆盖。  
4. 现有依赖 AgentRun 表体的读路径改为读 json（或明确迁移期双读），文档与代码一致。  
5. 默认保留 30 天的配置或常量存在且可测。

#### 冒烟

- 完成一轮含工具调用的提问 → 打开 json 能按时间戳还原顺序 → 用项目 ID 从 SQLite 索引定位到该文件。

## 6. 建议实现顺序

1. 引用清单（压缩前写入；带时间与取回键；上下文只带编号/短标题/时间；提供按编号取正文工具）。  
2. 默认窗口与压缩规则（8 轮、超 8 压缩最旧第 1～4、300 token；默认整池带入，不做剔除非今日）。  
3. 候选预览卡片 + 预览即实发 + token 预算。  
4. 三入口：直接回答 / 编辑 / 选更多历史。  
5. GenAI trace json 落盘 + SQLite 路径索引（取代 AgentRun 表体）。  
6. 分叉：新建分支按钮、复制摘要/近几轮/日期窗/引用清单、切换分支；**分支映射持久化，重启不丢**。  
7. 日期窗粗筛 + 群聊飞书历史细选（权限冒烟通过后再接群聊来源）。

## 7. 与长期记忆、Evidence、审计的边界

| 能力 | 谁负责 |
| --- | --- |
| 组装本次发给 Hermes 的业务消息 | 上下文管理器 |
| 项目记忆的审批写入与按需检索 | 长期记忆体系（卡片本期不勾选记忆） |
| 事实结论的证据绑定与校验 | Evidence / Verifier |
| 一次指令的完整过程存档 | GenAI trace json（取代 AgentRun 表体）；索引在 SQLite |

未出现在本次预览中的历史或群聊说法，不得被模型写成已确认事实。

## 9. 名词

| 名词 | 含义 |
| --- | --- |
| 上下文管理器 | 组装业务消息并发给 Hermes 的会话层能力 |
| 待发集合 | 预览卡片上展示、且实发唯一消费的条目列表 |
| 日期窗 | 会话/分支级粗筛日期范围 |
| 引用清单 | 压缩前或细选后可点名的短记录（含时间与取回键）；默认上下文只带元数据，正文按需工具取 |

| GenAI trace | 用户指令到本次回复完成之间的全部 messages 与相关状态 |
| 行动轨迹 json | 一次 GenAI trace 的整份落盘文件 |

## 10. 开放代办（不在本期实现）

1. **旧文档冲突清理**：降级/改写 Context Composer 与 Hermes 快照规划中与本文冲突的章节，并更新文档地图说明。  
2. **Trace 脱敏策略**：全量落盘后的凭证剥离、字段白名单、访问 ACL 与保留策略细化。  
3. **Skill 沉淀流水线**：另一 agent 读 json → 沙箱试跑 → 入库或标失败（本期只保证有可读轨迹）。
